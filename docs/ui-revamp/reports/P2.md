## 结果

P2 达到方案 §6.2 的退出标准，有一处行数目标略超（见“偏差”）。

- `src/main.zig`：17,666 行 → 4 行（只做转发）。

- 12 个宿主文件进入各 feature 的 `host/`：`ai_host` 7,413、`settings_host` 2,305、`nav_host` 2,287、`transfer_host` 1,818、`menu_host` 1,015、`child_dialog` 497、`wizard_host` 347、`notification_window_hook` 274、`chrome_mount` 188、`quick_connect_host` 98、`search_host` 36、`typography` 23。
- 11 个 feature 各有 `mod.zig` 门面（共 72 条再导出），`src/app/**` 只经门面引用 feature，签名自本阶段起冻结。
- `check-arch` 已挂到主程序与 6 个测试编译步骤上：此后新增违规会让构建失败。普通构建用固定参数的 `check_arch_gate`，`-Darch-args`（如 `--update-baseline`）只影响顶层 `check-arch` 步骤。

## check-arch 基线：689 → 802 条

净增 113 条。**全部是原本藏在 `main.zig` 里的引用被暴露出来，没有新引入的。** 依据：

1. P2 期间除 `src/main.zig` 外没有任何既有 `src` 文件被修改；旧的 689 条一条未删。
2. 113 条新增条目的来源文件全部是从 `main.zig` 拆出的 11 个 `host/` 文件。
3. 逐条核对目标：81 条指向旧 `main.zig` 原本就 `@import` 的文件；32 条指向本阶段从 `main.zig` 拆出的新文件（拆分前是同一文件内的引用）；不属于这两类的为 0。
4. 拆分是“剪切 + `pub` + import 别名”，方法体没有改动。

| 规则 | 条数 | 来源 |
|---|---:|---|
| cross-feature | 100 | 宿主代码原来在 `entry` 层（什么都能 import），进入各 feature 的 `host/` 后，它对别的 feature 内部文件的引用才被检查到。`nav_host` 37、`menu_host` 18、`ai_host` 11、`transfer_host` / `chrome_mount` / `settings_host` 各约 10 |
| host → app | 9 | 宿主访问进程级全局状态（`process_state`、`process_windows`），拆分前是同文件访问 |
| host → legacy_plugin | 4 | 向导、快速连接、导航宿主引用 `plugins/remote` 的编辑器 |

过程：拆分中累计暴露 193 条，门面提交让 `app` 只经 `mod.zig` 引用后消掉 80 条。这 113 条是 P5 用 Ports 解开宿主间具体指针依赖时的对象。从本阶段起基线受构建门禁保护，只能缩短。

## 偏差

- **`src/app/` 1,554 行，超出约 1,500 的目标 54 行。** `mountUI` 本体 745 行；方案设想把其中的配置加载、图标、菜单、主题选择提到 `startup.zig`，但这几段与后面的代码共用局部变量，切成函数必须改函数体，不算原样剪切，所以整体留在 `main_window.zig`。
- **去向与方案 §5.5 原表不同的三处**（方案已修订）：标题栏、侧栏、状态条的挂载函数进了 `shell/host/chrome_mount.zig` 而不是 `shell/view/`，因为它们创建宿主并接线回调；`onSocksChipClick` 随 `mountUI` 进了 `app/main_window.zig`；`mountUI` 没有拆出 `startup`。
- **`mod.zig` 目前多数是按文件导出的命名空间**，对应 `app` 里按文件引用的模块，P5 再收窄为具体符号。
- **越权**：P2 拆分子 agent 为零。
