# ZeroWork Zig 工程审查

基线：`a143a5bc`。审查覆盖 Zig 0.17.0 构建、架构门禁、原生回归清单、持久化和文件服务的资源边界。既有的 Zig 分层检查、静态 SSH 依赖校验、原子落盘与隔离 E2E 是可保留的约束。

| 优先级 | 问题和影响 | 本轮修改 | 定向验证 |
| --- | --- | --- | --- |
| P1 | 回归运行器能把没有执行的测试当作成功：空筛选或无效并发数可产生零条结果；缺少 Python 可以跳过已选用例。 | 启动前验证参数、选择集、超时、证据名称和测试夹具；仅当每个选中用例均通过时退出 0。 | runner 负向自测；文件工作区与回环 SFTP 的原生用例。 |
| P2 | 本地文本读取先检查文件类型后打开。路径若在两步之间换成 FIFO，无写端时工作线程会卡在 `open`，无法处理取消或关闭。 | 用非阻塞且不跟随最终符号链接的方式打开，读取前对已打开的描述符核对原快照；对所有错误路径关闭描述符。 | `test-ui` 的 `local fs` 组，含无写端 FIFO 的原生回归；回环 SFTP 文件工作区用例。 |
| P2 | 上下文压缩后总量更新而明细停在旧值。等值写入未替换列表信号的借用数据，轮换的内存却被重用。 | 明细文本交由各行的 owning signal 管理，列表与进度段复制值，保留行的身份。 | 打开的用量弹层经历状态重复与压缩数据更新；原生压缩和实时用量用例。 |
| P2 | stdio MCP 服务返回不支持新版握手的错误后，客户端留着这条已解析的回复，导致下一次旧版握手收到错误的请求 ID。 | 从缓冲区移除已解析的整条消息后再传播错误；原生夹具复用 E2E 的 Node 来提供旧版服务。 | 同一连接上的新版探测拒绝 → 旧版握手 → 工具发现；原生扩展用例。 |
| P3 | 部分原生断言依赖滚动容器的内部节点顺序、下拉菜单的首帧、SSH 已连接但终端尚未绘制的时刻，或假设所有本机 terminfo 都声明同一套可选能力。 | 通过稳定 ID 度量诊断内容；等待实际可观察状态；对未声明的能力在矩阵中显式标注，已声明的能力仍执行原断言。 | 恢复卡滚动、字重、SSH 分屏和三个终端类型。 |

先分别跑定向检查，再将提交集中到 `review/zig-integration`。从该分支构建测试应用和清单所需的全部预览产物，用默认的 `runnable` 类跑全量，包含标为 `e2e-debt` 的条目。用后续定向复跑定位失败；合入主干要求最终一轮完整通过。手工交互和真实外部服务继续按清单分类单独验收。

后续优先级：

1. 替换 [E2E 指南](../../e2e/README.md)中依赖本机绝对路径的全量命令。让构建入口从清单得到预览产物并预检，避免新增预览后漏建；验收标准是干净检出可复现同一批次。
2. 按所有权拆分工作区、AI 宿主和终端视图中的大模块。先给窗口销毁、后台任务和重连建立独立测试边界，再逐步缩小模块；单独按行数拆分没有可验证的收益。
3. 用实际空闲 CPU 与唤醒频率决定是否将本地文件工作线程的 2 ms 轮询改成事件通知；同时覆盖队列背压、取消和关闭，避免以减少 CPU 换取停止延迟。
